<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Request → /account RSC | Session decides which branch renders; user data is read only for the session user |
| Client forms → addGoal / deleteGoal / deleteAccount | Attacker-controllable FormData (goal fields, hidden goalId) |
| Delete confirm → Clerk sign-out | Client-side session teardown after the server has removed data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02 | Elevation of privilege (IDOR) | GoalList hidden goalId | mitigate | The id is only ever combined with the session userId in `deleteGoal` (`and(eq(id), eq(userId))` — 06-04); tampering with the hidden field cannot reach another user's row |
| T-06-01 | Spoofing | /account read | mitigate | `await auth()` in the RSC; `loadAccountSnapshot(userId)` receives only the session id; signed-out renders a prompt with zero data |
| T-06-05 | Information disclosure | Account client components | mitigate | Only action references, `import type`, and `@clerk/nextjs` client hooks; `goal-list.tsx` imports the row type with `import type`; guest-flow gate runs in every verify |
| T-06-06 | Tampering / Repudiation | Deletion flow | mitigate | Explicit confirmation dialog; the server action cascades DB before Clerk (06-04); client signs out only on `status === "ok"`; trigger label matches the privacy page instruction |
| T-06-04 | Information disclosure | Snapshot failure / action errors | mitigate | Null snapshot renders fixed neutral copy; components render only `ActionState.message` |
| T-06-16 | Denial of service (availability) | Static routes | mitigate | `auth()` is confined to `/account` and `/`; build gate confirms `○ /methodology`, `○ /privacy` unchanged |
| T-06-SC | Tampering | npm installs | accept | No packages installed in this plan |
</threat_model>
