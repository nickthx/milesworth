## Spacing Scale

Declared values (multiples of 4) — identical to Phase 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip inner padding |
| sm | 8px | Label-to-input gap, inline metadata rows, tap-target spacing between adjacent nav links |
| md | 16px | Card inner padding (mobile), gaps between form fields, horizontal page padding on mobile |
| lg | 24px | Card inner padding (desktop), gap between result cards, horizontal page padding ≥ `sm` |
| xl | 32px | Gap between form block and results; footer vertical padding; safe-area floor |
| 2xl | 48px | Section breaks (Bookable now / Almost there / advisor tease — `mt-12`), page top/bottom padding on mobile (`py-12`) |
| 3xl | 64px | Page-level top/bottom padding ≥ `md` (`md:py-16`) |

Exceptions:
- **44px minimum touch target (`h-11` / `min-h-11`) on every interactive element on every route.** Phase 4 applied this to inputs and CTAs; Phase 7 extends it to the two places that miss it today: the header "My account" link and the three footer nav items. Rule for text links inside `<nav>`: `inline-flex min-h-11 items-center` (the 14px text stays; the box grows). Footer nav gap becomes `gap-3` (12px — multiple of 4) so adjacent targets have ≥ 8px clear space.
- **Safe-area bottom padding.** One utility in `globals.css`: `@utility pb-safe { padding-bottom: max(--spacing(8), env(safe-area-inset-bottom)); }` applied to the footer container in place of its `py-8` bottom half. Desktop is unchanged (32px floor); iPhone home-indicator devices inside the LinkedIn WebView get the inset.
- **Card imagery aspect ratio 3:2** (`aspect-[3/2]`), which at the 360px floor (328px content width) yields a 219px-tall photo. Not a spacing token but the one fixed proportion this phase introduces.

## Typography

Two families, **two weights only: 400 (regular) and 600 (semibold).** Four sizes plus the single Phase 4 exception.

| Role | Size | Family | Weight | Line Height | Usage |
|------|------|--------|--------|-------------|-------|
| Label | 14px (`text-sm`) | Inter | 600 | 1.4 (`leading-5`) | Input labels, metadata rows, chips, eyebrows ("Coming soon"), "Verified …" stamps, nav links, footer text, "Last updated" |
| Body | 16px (`text-base`) | Inter | 400 | 1.5 (`leading-6`) | All prose, guidance, side-by-side figures, empty/sparse/error copy, **all inputs at every breakpoint** |
| Heading | 28px (**new token `text-heading`** = 1.75rem / line-height 1.2) | Fraunces | 600 | 1.2 | Section `h2`s, card titles, dialog titles, header masthead wordmark, `/account` saved-balance figures |
| Display | 48px (`text-display`, 1.1 / -0.02em) | Fraunces | 600 | 1.1 | Page `h1` on `/account`, `/methodology`, `/privacy`, error and not-found pages; per-card hero wow-delta figure |

Declared exception (carried from Phase 4, still the only one): `text-display-xl` (72px / 1.05 / -0.025em) is permitted **only** for the `/` page `h1` at ≥ `md`, clamping to `text-display` below. It is ink, sits above the balance form, and is never adjacent to a 48px card hero (cards are below the fold on mobile and separated by the form on desktop), which resolves the Phase 4 checker's non-blocking flag.

## Color

Three brand values, declared once in `src/lib/brand.ts` (`CREAM`, `INK`, `TERRACOTTA`) and mirrored in `globals.css` `@theme` (CSS cannot import TS; the design-system gate asserts the CSS hex strings equal the TS constants). `viewport.themeColor` and `og/route.tsx` read the TS constants — no hard-coded hex anywhere else.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-cream` **#faf7f2** | Page ground on every route; `themeColor`; `/og` background; `<html>` gets `color-scheme: light` |
| Secondary (30%) | White **#ffffff** (`--card`, input fill) + `--color-ink` **#262119** text | Result cards, teaser card, input surfaces; all headings, body, display text; **ink is also the primary button fill** (`--primary`) |
| Accent (10%) | `--color-terracotta` **#b25429** (re-tuned from #c05f33 — reason below) | Exactly the reserved list below |
| Destructive | `--destructive` existing `oklch(0.577 0.245 27.325)` | "Delete everything" confirm button only (Phase 6 locked) |
| Photography | Destination WebPs | The fourth "color" — see Imagery. Never tinted, never overlaid, never used as a text background |

**Accent (terracotta) reserved for exactly** (unchanged from Phase 4 — Phase 7 adds **no** new accent uses):
1. The per-card wow-delta hero figure (48px display) and the `/og` card headline delta
2. The primary CTA button "Copy my link" (white text on terracotta fill)
3. The active transfer-bonus badge ("+30% transfer bonus through …")

Everything else stays ink or ink/70: header, footer, links, focus rings, eyebrows, section headings, path text, chips, verified stamps, "points away" callouts, the Save / Sign in / Notify me / bookmark buttons, image captions, dialog buttons, error and not-found pages. The accent-budget grep (`text-terracotta` / `bg-terracotta` occurrences limited to `result-card.tsx` ×2, `core-experience.tsx` ×1, plus the `/og` route constant) remains a plan-time gate as in Phase 6.

**Why the accent hex moves (explicit reason to contradict a Phase 4 value):** WCAG relative luminance of #c05f33 is 0.196. White text on it is 4.26:1 and the 14px badge on white is 4.26:1 — both **below the 4.5:1 AA floor for normal text**, and terracotta on cream is 3.99:1 (the Phase 4 note claiming ≈4.6:1 was miscalculated). Lighthouse's `color-contrast` audit is part of the accessibility category this phase gates on. #b25429 (luminance 0.160) gives **5.0:1 white-on-terracotta, 5.0:1 terracotta-on-white, 4.7:1 terracotta-on-cream** — AA for normal text on every surface it appears on, and 48px display use clears AAA-large. It is a visibly-identical warm terracotta (slightly deeper). One token change; the `/og` route picks it up through `brand.ts`.

**Warm neutrals (replaces shadcn's achromatic oklch defaults in `:root`).** All derived from ink with plain rgba alpha — no `color-mix()` in hand-written CSS (research A6), no new hue:

| Variable | Value | Effective use |
|----------|-------|---------------|
| `--background` / `--foreground` | #faf7f2 / #262119 | unchanged |
| `--card` / `--card-foreground` | #ffffff / #262119 | white cards, ink text |
| `--popover` / `--popover-foreground` | #ffffff / #262119 | Clerk modal chrome, dialog |
| `--primary` / `--primary-foreground` | #262119 / #faf7f2 | default `Button` = ink fill, cream text ("Notify me", "Add goal") |
| `--secondary`, `--muted`, `--accent` (shadcn hover surfaces — **not** the design accent) | `rgb(38 33 25 / 0.05)` | outline-button hover, card footer tint (`bg-muted/50`) |
| `--secondary-foreground`, `--accent-foreground` | #262119 | |
| `--muted-foreground` | `rgb(38 33 25 / 0.7)` | same value as the `text-ink/70` convention |
| `--border` | `rgb(38 33 25 / 0.12)` | card rings, header/footer rules (matches today's `border-ink/10` family) |
| `--input` | `rgb(38 33 25 / 0.24)` | input borders — heavier than `--border` so white inputs read as controls on cream |
| `--ring` | #262119 | vendored `focus-visible:ring-3 ring-ring/50` composites to ≈#908c86 on cream = 3.5:1, meeting the 3:1 non-text floor; `focus-visible:border-ring` is full ink |
| `--destructive` | unchanged | |
| `--chart-*`, `--sidebar-*` | delete (unused) | |
| `.dark { … }` block | **delete** | inert today; a liability if a `dark:` class ever activates |
| `@custom-variant dark (&:is(.dark *))` | **keep** | Removing it would make Tailwind's default `dark:` (media-query) variant activate the vendored `dark:` classes on phones set to dark mode — exactly the recruiter-in-LinkedIn case |
| `html { color-scheme: light }` | **add** | Native controls, the date input, scrollbars, and the Clerk modal stay light inside a dark-mode WebView |

Contrast ledger (WCAG, computed): ink on cream 17.7:1; ink/70 (≈#66615a) on cream 5.7:1, on white 6.1:1; terracotta #b25429 on white 5.0:1, on cream 4.7:1; white on terracotta 5.0:1; cream on ink (primary button) 16.6:1. `--input` at 24% ink on white is ≈1.9:1 — below the 3:1 non-text guideline, accepted as an editorial choice because every input also has a visible label, white fill on cream, and a placeholder; Lighthouse does not audit it (assumption A8).

## Imagery Contract

This is the piece of PLAT-05 the codebase has none of today ("destination imagery"). CLAUDE.md fixes the pipeline (source once, pre-crop, WebP ~1600w, commit, static `next/image` imports, `imageSlug` → typed manifest, never hotlink); this section fixes what the executor renders.

| Rule | Value |
|------|-------|
| Placement — YES | (1) `ResultCard` (Bookable now tier): the Card's leading child, full card width, before `CardHeader`. (2) The empty-state featured teaser card on `/`: same treatment — the first card a fresh visitor sees is the magazine moment. |
| Placement — NO | The `/` hero (type-only: the `h1` must stay the mobile LCP element — research Pitfall 8). "Almost there" cards (keeps the drama and the image bytes in the tier that is bookable; visually separates the tiers). `/methodology`, `/privacy`, `/account`, error, not-found, loading (reference pages stay type-only). Header, footer, `/og` (Satori card stays typographic). |
| Asset | `src/images/destinations/<imageSlug>.webp`, 1600×1067 (3:2), sharp `fit: "cover", position: "attention"`, WebP quality 75, effort 6, metadata stripped; **≤ 200 KB per file**; 20 slugs today (tokyo, singapore, hong-kong, hawaii, london, paris, frankfurt, dubai, istanbul, doha, amsterdam, big-sur, kauai, austin, cancun, maldives, bora-bora, maui, kyoto, venice) plus one per new destination the dataset batches add |
| Manifest | `src/images/destinations.ts`: `Record<ImageSlug, { image: StaticImageData; alt: string; credit: { photographer: string; source: "Unsplash" \| "Pexels" } }>`; `getDestinationImage(slug: string \| null)` is a typed map lookup and returns `null` for unknown/null slugs — never a filesystem path |
| Render | `<Image src={art.image} alt={art.alt} placeholder="blur" sizes="(min-width: 768px) 768px, 100vw" className="aspect-[3/2] w-full object-cover" />` — lazy (default), **no `preload`/`priority`**, no `fill`, no `unoptimized` |
| Missing image | If the lookup returns `null` the card renders exactly as it does today (no placeholder box, no broken-image glyph). The image-manifest test makes this unreachable for seed data; the branch exists for type safety |
| Corners | Card is `overflow-hidden rounded-xl`; the vendored `*:[img:first-child]:rounded-t-xl` + `has-[>img:first-child]:pt-0` rules already handle the leading image — do not add wrapper divs around the `<Image>` or those selectors stop matching |
| Treatment | Photograph only. **No** gradient, tint, duotone, vignette, or text overlay; **no** caption bar. The card title sits below the photo in ink on white — text never sits on a photo (contrast + the light aesthetic) |
| Alt text | Descriptive of the destination scene ("Overwater villas at dusk, Maldives"), 4–10 words, not the redemption title (the title is already the card heading — repeating it is redundant for screen readers) |
| Photo selection | Daylight or golden hour; light, warm, editorial (Condé Nast Traveler, not stock-tropical). Landscape, cityscape, or architecture of the destination. **No** airplane cabins, lounge seats, hotel logos, people as subjects, or heavy HDR/night shots (they darken the page and fight "light, magazine-like"). One image per slug, reused across redemptions that share a destination |
| Credits | Manifest holds photographer + source. One visible line in the footer nav, plain text, 14px ink/70: **"Photos via Unsplash"** (or "Unsplash and Pexels" if both are used). No external link — no third-party dependency in the demo path, no `target="_blank"` (Pitfall 6) |
| Performance | Images are below the fold at 360px (8-input form ≈ 700px tall precedes them); lazy loading means a share-link visit downloads only the cards scrolled into view. `next/image` serves AVIF/WebP responsive variants; the `sizes` value caps desktop at the 768px rail |

## Accessibility

- Contrast: every text/background pair in the Color ledger is ≥ 4.5:1 (normal) or ≥ 3:1 (display sizes); the accent re-tune exists for this reason.
- Focus: visible on every interactive element via the vendored `focus-visible:border-ring focus-visible:ring-3 ring-ring/50` with `--ring` = ink (≈3.5:1 halo on cream). Never `outline-none` without a replacement.
- Landmarks: one `<main>` per route; `<header>`/`<footer>` from the layout; `<nav aria-label>` on both nav groups; sections labelled by their visible `h2` (`aria-labelledby` where the section has no heading element).
- Heading order: exactly one `h1` per route; `h2` for sections; card titles are `CardTitle` divs styled as headings (unchanged from Phase 4) — do not promote them to `h3` inside `<li>` without reviewing the outline.
- Images: descriptive `alt` from the manifest; no decorative images (every photo carries meaning), so no empty `alt`.
- Live regions: label swaps ("Link copied", "Saved") and the advisor status keep their `aria-live="polite"`; the clipboard fallback field, when it appears, gets focus moved to it once (it replaces the expected "Link copied" feedback).
- Zoom: never disabled; text reflows to 320px without loss.
- Motion: none added, so `prefers-reduced-motion` needs no handling this phase.
- Color alone: the bonus badge is terracotta **and** carries the "+N% transfer bonus" text; bookmark state is a label change ("Saved to my account"), not a color change.
